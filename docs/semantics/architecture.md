# 架构

本文只写最抽象的一层：系统里有哪些角色、每个角色默认跑在哪个位置、角色之间流什么。将来的扩展一般是把某个角色搬到另一个位置；角色可以增加，但增加角色必须改本文。产品功能在 `product/` 分册，具体机制在 `mechanism/` 分册。

## 角色

| 角色 | 负责什么 |
|---|---|
| **编辑界面** | 用户看和操作的地方 |
| **文档服务** | 项目文档的唯一修改入口：接收人和 Agent 的操作，排序、记版本、通知各方。各方手里的项目都是它的副本。它是通用的文本 / JSON 调度分发中心，预渲染的任务队列是挂在它上面的模块之一：只记账，不分配（见 `product/document-service.md` 的「职责」「渲染任务队列」） |
| **素材服务（Asset Service）** | 字节的唯一读写入口：原视频、素材、预渲染的产物都经它存取。只管字节，没有项目语义 |
| **成片渲染** | 把项目渲染成给人看的画面 |
| **即时渲染** | 按需渲染指定时刻的画面直接交给请求方（如 Agent），供其观察或使用；不经过素材服务（取代旧名「查询渲染」） |
| **Agent** | 读项目、发出修改、请求即时渲染。可替换：本地模型、用户自己的 API 服务、本机 CLI / 桌面 APP Agent，对其它角色是同一种角色 |

## 默认位置（单机单用户模式）

```
用户设备（本机）                  本机服务
┌──────────────────────┐        ┌──────────────┐
│ 编辑界面             │ 操作 → │ 文档服务     │
│ 成片渲染             │ ← 通知 │              │
│ 即时渲染             │        ├──────────────┤
│ Agent                │ 字节 ↔ │ 素材服务     │
└──────────────────────┘        └──────────────┘
```

- **用户设备**：编辑界面、成片渲染、即时渲染、Agent。
- **本机服务**：文档服务和素材服务是两个分开的本机服务，监听 `127.0.0.1`。编辑界面和 Agent 只认服务的接口。
- **连接发现**：素材服务 URL 的动态下发作为基础设施发现功能保留，由文档服务把素材服务的本机地址下发给各方。文档服务只做地址下发，不承担素材传输流量。

## 数据流

- **操作和通知**只走文档服务。编辑界面和 Agent 都向它提交操作、从它收别人的操作。任何一方不得绕过它改项目。
- **字节**只走素材服务。原视频、素材、预渲染的产物的一切读写都经素材服务的接口，不经过文档服务；任何一方不得绕过它直接读写字节。预渲染的产物生成后一律推送到素材服务。
- **预渲染任务**的发布、认领和完成通知走文档服务，只传小消息；任务的输入（项目、素材）和产物都按上一条走素材服务。
- **Agent 看画面**有两条通道：
  - 实时看画面走即时渲染，结果从渲染所在的位置直接回传给 Agent，不经过素材服务。
  - 审阅成片时，经素材服务拉取预渲染的产物。

人机协作规则：**最后写的赢；发生覆盖时，覆盖方和被覆盖方都要知道。**（见 `product/document-service.md`）。

## 扩展点

| 搬什么 | 搬到哪 | 状态 |
|---|---|---|
| 成片渲染 | 独立渲染进程 | 预留 |
| 预渲染 | 本机渲染节点经文档服务的任务队列认领 | 已做 |

搬动的前提：角色之间只靠上面三条数据流说话。
