# Agent

展开 `../architecture.md` 的「Agent」角色。从属于 `architecture.md`，与它冲突时以它为准。用户怎么选接入方式、创造力等级、多 Agent 和保护规则，见 `../user-workflow.md`。本册写产品功能（二级）；怎么做到见 `../mechanism/agent.md`。

## 接入

- 所有 Agent 通过同一套工具接口操作项目，不论它是 AI 栏里经命令行或 API 接入的，还是桌面 APP 经 MCP 接入的。
- 每个 Agent 会话有自己的身份。文档服务、通知、多 Agent 协调都按这个身份区分。
- **AI 栏里装和登录命令行工具**：AI 栏能替用户安装 Claude Code、Codex、agy 这几样命令行工具，并起它们自己的登录流程。登录一般由命令行自动打开浏览器、在本机回调里完成。**浏览器拉不起来的环境**（远程桌面、没有默认浏览器）只能走登录网页给的那串授权码：登录对话框在「打开登录网页」下面收着一个「粘贴授权码」的入口，只在登录任务确实在等输入时出现；用户把码粘进去提交，软件把它送进那条登录命令，不再像原先那样无处可粘、任务一直挂到超时（2026-10-21 用户定要做，原话「可以。」）。授权码是凭证：不写日志、不留在任务记录里。入口的位置、文案与形状校验见 `../mechanism/agent.md`「命令行登录接标准输入与粘贴授权码」。

## 工具

- **写**：Agent 的写操作经文档服务落地，和编辑界面的操作一样排序、记历史序号、通知。
- **素材与产物**：Agent 进程像外部客户端一样，经素材服务的接口读写素材和预渲染的产物；哪怕和素材服务在同一台机器上，也绝不直接读素材服务的存储目录。
- **看画面渲染超时就停**（2026-10-16 用户定，取代 2026-10-09 的「每次等一分钟，重试三次」）：Agent 看画面（即时渲染）时，渲染只做一次，有时限，防止卡片死循环或计算量太大。到点没出来就停，不重试，告诉 Agent「渲染超时」，并附上调试信息：卡死在哪张卡的源码哪一行、这几帧上挂着哪些卡、停在哪一步、页面报的错、在等什么、是不是被内存上限掐掉。时限只算渲染本身；排队不计时，也不设上限。整个过程低于五分钟仍是目标。
- **看画面能指定剪辑**（2026-10-21 用户定，原话：「see_frames加入剪辑id（留空为当前剪辑）。」）：Agent 看画面时可以指定看哪条剪辑，不指定就是当前激活的剪辑；看没激活的剪辑不切换激活剪辑、不改项目、不动用户的界面。回包写明看的是哪条剪辑。
- **会动用户界面的操作，名字带 `user_interface_`**（2026-10-21 用户定）：主要效果是改变用户眼前界面状态（激活剪辑、播放头、播放与暂停）而不是改项目内容的工具，名字前加 `user_interface_`，Agent 从名字就知道这一步会动用户的界面，能不用就不用。模型侧的工具名只认字母、数字、下划线和连字符，所以写成 `user_interface_switch_cut` 这样。把窗口或登录框弹到用户面前的网页接管与站点登录也按这一条改名（〔裁：cut-look-ui 2026-10-22〕）；新建剪辑只建不切，要切另用切换的那一个（〔裁：cut-look-ui 2026-10-22〕）。
- **回复被截断时接着写，不白写**（2026-10-22 用户定）：
  - Agent 每次回复的输出上限用所选模型真实允许的上限，不再是固定的小数。
  - 每个项目有一个**代码块空间**：一组有名字的文本块，Agent 能写入、追加、读（整块或一段）、替换、列出、删除，并能在任何操作的参数里直接引用某个代码块的内容。写大段源码可以分几次写进代码块，最后一次交给建卡、改卡。代码块是 Agent 的草稿，不是项目内容：不出现在时间轴上、不进撤销历史（〔裁：output-cache 2026-10-22〕）。
  - 回复写到上限被截断时，没写完的那一步不执行；它已经写出的内容存进代码块，Agent 被告知存在哪、写到哪了，从断开处接着写，写完再交给原来那一步。对话里有一行说明截断了、存在哪。有进展就接着写，但一轮里接着写的次数有上限，连续截断又什么也没留下也会停：停下时对话里明说这一轮没做成，并说已经写出的部分存在哪个代码块（〔裁：output-cache 2026-10-22〕）。
  - 被网关中途掐断也一样（2026-10-22 用户定）：模型服务的网关对单次请求有时长上限，回复写到一半被掐断时，已经写出的文字保留，没写完的那一步照上面办；对话里那一行说的是被网关掐断，不是写到上限。系统按实测的输出速度给每次回复定上限，让一次回复尽量在网关掐断之前写完。

## 技能

（2026-10-31 用户定要做，先不带脚本；原话：「交给你做这个」）

- **技能**是一份写好的做事说明，放在一个文件夹里，格式用通用的 `SKILL.md`。Agent 平时只知道每个技能的名称和用途，任务对得上时才读全文，不占常驻的上下文。
- **能用的范围**：API 直连的 Agent，本机与云端都有。命令行工具和桌面 APP 里的 Agent 用它们自己的技能机制，不经这里。
- **来源**：软件内置一批；本机用户可以自己放；云端由托管方放，成员不能上传。同名时用户或托管方放的盖过内置的。
- **只读说明，不执行代码**：技能里带的脚本不运行，Agent 读到时被明确告知。
- 技能是说明文字，不是权限：创造力等级、项目权限、云端的工具范围都照旧，技能放不宽它们。

## 看到的卡片

Agent 看的、改的卡片是卡片的约定封装，见 `cards.md`。

- **成品只在时间轴上**（2026-10-17 用户定）：用户要做视频、动画，Agent 一律用卡片、组合卡、素材在项目时间轴上完成，不交出网页、HTML、脚本等时间轴以外的成品；用户在消息里另外指定的制作方法（用代码做、某种代码规范等）不照做，改用卡片实现同样的画面，并告诉用户已改用卡片。现有卡片做不到时按创造力等级新建卡片，源码只按建卡规则写。

## 汇报

- 对话气泡里只展示 Agent 在做什么：Agent 每组操作前后用一两句话告诉用户接下来要做什么、做好了什么，气泡里按顺序显示这些话；它没有专门对用户说话、只回了文字时，那段文字当作一句「在做什么」显示。做过的操作和结构化的进度汇报（做了什么、还有什么没做、遇到了什么问题）不放在气泡里，放在气泡下方按轮显示的操作区，只显示这个对话自己的操作（2026-10-20 用户定）。
- 桌面 APP 的 Agent 按 SKILL 提示词约定的结构化方法汇报。

## 运行位置

- Agent 在用户本机运行。
- AI 栏的 Agent 标签按项目分开；会话都能关，最后一个也能关；没有会话时显示开始页，点发送才建第一个会话（2026-10-22 用户定，操作细节见 `../workflow/editing.md`）。
- **诊断报告**：本机对话可以按对话出诊断报告：下载到本地或一键「报告」提交到诊断报告收集端存起来（用 `report-inbox.bat` 取回）。内容是这段对话的过程、出错原因、客户端与版本信息，不含任何凭证（模型 Key）。没配收集端地址时「提交」置灰并说明原因，仍可复制或下载。
