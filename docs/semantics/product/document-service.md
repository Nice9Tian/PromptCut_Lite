# 文档服务

展开 `../architecture.md` 的「文档服务」角色。从属于 `architecture.md`，与它冲突时以它为准。本册写产品功能（二级）；怎么做到见 `../mechanism/document-service.md`。

## 是什么

即时的文本信息中转站：接收各方的小消息，排序、记历史序号、转发给该收到的人，并记录项目和任务的进度。它只记账，不算账：没有渲染能力，不测算力，不派任务。

## 不是什么

不是计算服务，不是存储服务。

## 职责

- 文档服务是项目文档的唯一修改入口。编辑界面和 Agent 都只向它提交操作，由它排序、记历史序号、通知各方、管理锁。各方手里的项目都是它的副本。
- 它管理：项目信息、每一次操作的接收与分发、锁、覆盖通知、卡片源码、渲染任务队列。
- 它和每一方之间是一个会话（见下文「会话与传输」），传小消息、要求快速响应。素材字节和预渲染结果不走会话，走素材服务。
- 它是通用的轻量文本 / JSON 调度分发中心：渲染任务队列只是挂在它上面的模块之一；以后与渲染无关的文本消息模块也可以挂上来。无论挂什么模块，都只传小的文本消息，不传字节。

## 会话与传输

- 文档服务与每一方之间是一个**会话**。会话内的消息双向有序、带序号，接收方确认收到。
- 本地文档服务通过 WebSocket（`/docservice`）与编辑界面、Agent、渲染节点通信。

## 连接发现

- 文档服务只下发素材服务地址，不承担素材传输流量。

## 版本与身份

- 每次写入都带写入者的身份：是编辑界面的哪个页面，或哪个 Agent 的哪个对话。
- **本机按真正的发起方判断**：本机上的编辑界面和进程连本机的文档服务，不用交凭证。「本机」按连接真正的发起方判断：经同一台机器上的反向代理转进来的连接和请求按远端对待并拒绝。

## 冲突

- **发生覆盖时，覆盖方和被覆盖方都要知道。**
- **共用的「冲突合并」窗口与导航栏入口**（2026-10-18 用户定）：用户按撤销按钮（含 AI 栏的「撤销这一步」）遇到之后被 Agent 或自己改过的冲突时，使用「冲突合并」窗口按修改项逐条勾选合并或删除。
- 某张卡最近的写入者在新历史序号落地时收到通知；Agent 和用户都可以对某张卡退出跟踪。
- Agent 的写操作带期望历史序号，和当前历史序号不符就拒绝，并告诉它期间落地了哪些改动，由它重读后再改。用户在页面上的操作不带期望历史序号，按到达顺序落地。
- 两个 Agent 在短时间内反复交替改同一张卡时，锁住先写的那一方对这张卡源码的写权限，并通知双方和用户；由用户解锁，或空闲一段时间后自动解锁。

## 渲染任务队列

预渲染任务由文档服务托管的任务队列管理，本机的预渲染进程作为**渲染节点**从队列里取活。

- **只记账，不分配**：文档服务只记每个任务的状态和认领者，不测算节点的算力，不主动把任务派给谁，也不替节点判断它做不做得了。唯一的例外是指纹前置过滤（见 `../mechanism/document-service.md` 的「渲染任务队列」）。
- **任务不带字节**：任务只写要渲染什么（项目历史序号、片段、帧范围、预渲染结果的内容键），不带项目文件以外的字节。节点按项目历史序号从文档服务取项目，按哈希从素材服务取素材。
- **离线兜底**：连不上文档服务时，本机的预渲染进程照常为本机的项目做预渲染，不经过队列；恢复连接后照机制里「队列只在内存里」那一条重新发布（见 `../mechanism/document-service.md` 的「渲染任务队列」）。
