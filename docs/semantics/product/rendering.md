# 渲染

展开 `../architecture.md` 的「成片渲染」「即时渲染」两个角色。从属于 `architecture.md`，与它冲突时以它为准。卡片的分类见 `cards.md`。本册写产品功能（二级）；怎么做到见 `../mechanism/rendering.md`。

## 总规则

- **交互不等渲染。** 用户交互不允许任何卡顿：舞台渲染和用户交互互相异步，交互永远不等渲染。画面来不及时，只允许按「兜底顺序」（见「重管线：预渲染」）退化：先用低帧率或旧的预渲染结果顶上；只有算力预算装不下、或没有任何可用的预渲染结果时，才在该层显示占位符。预览里任何一层都不无提示地透明。打开项目时的测量遮罩是唯一的例外。
- **同一时刻同一帧。** 预览、导出、Agent 看到的画面用同一份卡片代码、同一套钉时间的方法，同一时刻渲染出同一帧。
- **帧率。** 最高 60 fps。项目可选 24、25、30、60，新项目默认 30，所有时间步长按 1/fps。

## 用到的词

- **活渲**：卡片在舞台里当场一帧帧算出来、画上去。
- **轻卡、重卡**：当场画得过来的卡是轻卡，直接活渲；画不过来的是重卡，事先渲好、播放时贴上去。哪张轻哪张重靠实测，同一张卡在项目的不同位置可以不同。
- **剪辑段里的卡和没有剪辑段时一样**：轻卡活渲，重卡各自走轨道流，没流时显示占位（2026-10-21 用户定）。
- **轨道流**：重卡事先渲好的带透明的视频，播放、暂停、拖动时贴上去。先有隔一段截一张的稀疏版，再补成每帧都有的满密度版。
- **实体框**：卡片实际画出内容的最小矩形。
- **兜底顺序**：画面来不及时，按从好到差的顺序找能用的画面顶上；都没有才显示占位符。

## 舞台

- 给人看的画面在舞台里渲染。桌面版舞台里的卡片代码不许调本机编辑器进程与预渲染进程的接口，按哈希读素材只放行当前项目（2026-10-14 用户定）。舞台和编辑界面分属不同进程/源，舞台卡住时编辑界面不卡。

## 播放

- **按帧走，慢帧就等。** 舞台每渲完一帧才推进 1/fps，并报告当前时刻；某一帧慢了就把后续整体后移，不追、不跳帧。
- **播放头跟随舞台。** 编辑界面的播放头跟随舞台报告的时刻。
- **看不到推帧过程。** 拖动或点击时间轴随机跳转时，用户看不到推帧卡被推进的中间过程。
- **停下就精确。** 暂停、点击时间轴、拖动时间轴后松开，以及播放到头停下，所有卡都回到精确的活渲。
- **音频跟随画面。** 画面落后应到时刻太多时暂停音频；恢复时对齐到当前时刻。

## 轻卡与重卡

### 测量

- 每次打开项目，在加载遮罩下把所有卡测完，并给判重的卡产一套稀疏的轨道流，才进入编辑；产得久的到时限就先进编辑，剩下的闲时接着产。之后新加的卡在后台舞台里测。

## 重管线：预渲染

- 重卡离屏预先渲染成预渲染结果。播放和拖动时只贴预渲染结果，拿不到这一帧时按下面的兜底顺序处理，播放头从不为它停。
- 需要预渲染的卡作为任务发布到文档服务的任务队列，由本机渲染节点认领（见 `document-service.md` 的「渲染任务队列」、`platforms.md` 的「渲染节点」）。连不上文档服务时本机照常自己做。
- **不同环境的结果不混用**：不同硬件渲的连续帧拼在一起会闪，所以同一层里的帧只出自一种环境，画面不闪。
- 预渲染结果生成后一律推送到素材服务，见 `asset-service.md` 的「预渲染的产物」。预渲染进程经素材服务的接口推送产物、读取素材，不直接读写素材服务的存储目录。
- 预渲染结果只有按项目分辨率渲出的轨道流一档。
- **先稀疏后满密度**：重卡的轨道流先产稀疏版，把整段铺满，再补成满密度版。之后要补的只在暂停时产，播放时不产；稀疏版排在满密度版前面。
- **切分长度**（2026-10-14 用户定）：motion 式的卡产流任务拆分至少管 30 秒（30fps 下 900 帧，比 30 秒短的卡整张一口气做完）；remotion 式卡保持 8 个分段（4 秒 / 120 帧）一个任务。
- 暂停后，重卡追到精确活渲。

### 兜底顺序

- 只有两种情况退到占位符：该层所有兜底都超出预算；或该层还没有任何预渲染结果。
- 占位符：在该卡的实体框位置显示「沙漏 + 噪点」，表示系统正在加载；量不到实体框时只在位置框中心显示一个小沙漏徽标，不铺噪点。它继承该层的坐标、旋转、缩放和层级，自身几乎不占算力（不跑脚本、不逐帧重绘，动画只动合成属性；同屏多个时只有一个沙漏在转）。
- 其它来不及的时刻也用占位符，不透明：轨道流的这一帧还没到、不可见地追帧、等后台舞台补跑后互换。
- 来不及的状态很短时不显示占位符，避免闪烁。
- 占位符只出现在编辑界面的预览里；导出、预渲染、Agent 看到的画面和后台舞台永远没有它。
- **3D 剪辑的成片路径同样没有中间态**（2026-10-24 用户定）：3D 剪辑把每张卡当成立在空间里的一块板子、板子上贴那张卡的画面，而检视用的 3D 视图在贴图还没到位时先画一块半透明代理色块、渲好了换上。**代理色块是检视视图的行为，成片路径一律没有它**：导出、预渲染、Agent 看到的画面要么拿到那张卡这一刻真正的画面，要么等它，不画代理色块、不画占位符、也不留空。这和上一句是同一条规则，单独写出来是因为 3D 剪辑的板子多了一条「贴图」这一步，容易在那里漏出中间态。
- 更好的结果到货后自动替换，不等用户操作：稀疏段换成满帧段在下一个分段起换上（两种编码的差分帧不能接续）；暂停着的时候原地换上（向左对齐，只取不晚于当前帧的画面，属于兜底规则，不影响「停下就精确」；2026-10-14 用户定）。
- 停下就撤兜底：暂停、点击或拖动松开时，兜底画面一律撤下、追到精确活渲；之后不再盖回去，直到下一次跳转或播放。

## canvas 卡的共享 WebGL 渲染器

- canvas 卡的渲染路线有两条，项目选项可切换：缺省每个舞台各用一套；可选两个舞台共用一套。
- **画布卡产流一律直取像素**（2026-10-14 用户定）：画布卡（canvas 卡）产轨道流一律直接从画布取像素交给编码器，不再每段实测对比。

## 即时渲染与预渲染进程

- 即时渲染的结果从渲染所在的位置直接回传给请求方（Agent 等），不经过素材服务。
- **单项目模式**：只为一个项目干活，整个项目装进来一直留着，这个项目之后的请求都在装好的项目上做。桌面版的预渲染进程用它。
- **Agent 优先只是插队**：Agent 的即时渲染不霸占渲染，用户总能等到预渲染。
- **AI 栏的操作预览可以插队**：它由用户触发，排到普通预渲染队列所有待办任务之前，不打断正在跑的那一批，也不占用 Agent 的专用实例。
- **单卡画面（bake_card 与 3D 视图贴图）**（2026-10-14 用户定）：播放时取卡片自己的轨道流（稀疏版也可，向左对齐；无流先占位；打开 3D 模式时轻卡也产轨道流，贴图随播放时间动）；暂停时当场渲当前帧（和 2D 预览「停下就精确」一致）；导出时逐帧高清活渲，不从流里取。单张卡片出图统一称为「PNG 快照」。

## 导出

- 桌面版导出由预渲染进程逐帧导出。

## 有声动效卡

- 画面与声音属于同一片段，共用源时钟。持久音频产物替代该片段的实时合成播放源，不能同时播放两份。
- 预览时，未生成、缺失或过期的声音必须提示。声音继续沿用本册「音频跟随画面」的规则。
- **导出时自动生成声音**（2026-10-06 用户定）：导出开始时，先把所有未生成、缺失或过期的声音生成好，再开始出画面。生成进度算进导出进度，取消导出同时取消生成。只有某段声音确实生成不出来时导出才失败，并说明是哪个片段；导出不得悄悄省略声音。
