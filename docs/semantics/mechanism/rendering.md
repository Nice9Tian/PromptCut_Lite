# 渲染：机制

本册写 `../product/rendering.md` 背后的具体机制（三级），从属于它，与它冲突时以它为准。

## 总规则

- 切换帧率后，全部成本记录和预渲染结果作废，重新测量。

## 舞台

- 舞台有两个，角色可以互换：
  - **可见舞台**：用户看到的画面，负责播放。
  - **后台舞台**：负责测量卡片成本，以及为只能靠全局时钟推进的卡整场景补跑，补跑完与可见舞台互换。逐帧生成时，每推一帧都把这一帧排下的界面更新提交完再往下，所以接着上一帧做和从挂载帧重新推，得到同一份快照〔裁：2026-10-13 `claude/rr-push-exact`，出处 `docs/reports/AGENT-rr-push-exact.md`（三级）〕。
- 桌面版舞台锁死：舞台里运行的卡片代码不许调本机编辑器进程与预渲染进程的接口；按哈希读素材只放行当前项目（素材不能跨项目读取）。
- 舞台接管全部计时方式（`performance.now`、rAF、`Date.now`、定时器），时间只由舞台的时钟给。`Date.now` 固定为一个纪元，不取真实时间。推帧时每一帧的时刻按帧号直接算（帧号 ÷ 帧率），不逐帧累加；动画被拨到结尾时，它的结束回调由舞台当场交付，不等浏览器出帧。

## 播放

- **音频跟随时刻。** 舞台的某一拍比应到时刻晚出超过 40 毫秒，就暂停音频；恢复时对齐到当前时刻。阈值固定 40 毫秒，不按帧率换算。

## 轻卡与重卡

轻重靠实测，不靠声明。轻卡在可见舞台里活渲，重卡贴预渲染结果。

### 测量

- 卡片和它依赖的对象的身份（参数、源码版本、帧率、审阅表、机器与渲染路线）都没变时，直接复用上次的测量记录。
- 每张卡测这几个数：
  - **活渲单帧耗时**：取多帧的稳健统计值，缺省为第 90 百分位、至少 16 帧；单次最大值另记，只作诊断。这是唯一进入判重的数。
  - **追帧总耗时**：推帧卡从第 0 帧推到最后一帧的活渲耗时之和。
- 测量分两趟：第一趟只计时；第二趟给判重的卡产一套稀疏的轨道流（每 15 帧一张，见「重管线：预渲染」），桌面由预渲染进程在全部卡测完以后产。遮罩下产稀疏版最多等 50 秒，到时就先进编辑，剩下的闲时接着产。
- 成本倍率、取第几百分位、最少采样帧数是可调系数，调它们不改预算公式，也不改代码。

### 分派

- **预算** B = 1000 / fps × 70%。
- 活渲单帧耗时超过 B 的卡，在所有位置都判重。
- **按位置分派**：所有卡片的入点和出点合起来作为分段边界，每一段各算一次。在每一段里用贪心搜索，按每拍的实际成本从小到大把卡纳入轻管线，直到再加一张就会超出预算，其余为重卡。
- **推帧卡按最差情况算**：需要不可见追帧的卡，按从第 0 帧追到最后一帧的总代价判，总代价在追帧预算内才能进轻管线，这样跳到片段最后一帧也追得上。
- **实际追多少帧按位置估**：播放头落在 t 时，长推帧卡实际要追的帧数按 (t − 入点) × fps 估。这只决定追多少帧，轻重仍按整段最差代价判。
- **人工钉死为重卡**：用户或探针可以把一张卡钉死为重卡（`pinnedHeavy`）。钉死的卡不参与轻重判定，直接进预渲染集合；它和降级一样是判重的输入之一。
- **预渲染集合**：所有段里重卡的并集。只在所有段都判轻的卡不产任何预渲染结果；任一段判重的卡，整段完整预渲染。可见舞台在每一段按该段的轻重结果处理。

### 有声动效卡的画面成本
〔用户 2026-10-06 定:「直接自动即时补测试。不要默认判重。」〕画面是组件、另写了 `audio()` 的有声动效卡，它的画面就是一张普通的 DOM 卡：第一次要用时自动即时测量，测完按结果判轻重，不默认判重。做法：成本身份的节点取片段自己的卡节点（`pipelinePlan.mjs` 的 `clipCostNodes`），图里的节点不动，所以预渲染结果的键不变。

## 轻管线：活渲

- 轻卡永远在可见舞台里活渲。
- 跳转时：可定位的卡直接钉到目标帧；短的推帧卡当场从起点逐帧推到目标，中间态不画出来；长的推帧卡不可见地追，追上再显示。能用自己子树的虚拟时间推进的卡在可见舞台里追；只认全局时钟的卡由后台舞台整场景补跑后与可见舞台互换。连续播放中逐帧走过挂载帧、自然进场的卡不是跳转，不互换；从卡中间开始播放的照跳转办。
- **降级**：播放中任一秒内，每拍超出 1/fps 的部分累计超过 1/fps，就把这一秒实测最贵的一张轻卡降为重卡。降级不立即生效：这张卡先进预渲染队列，排在正在跑的那一批之后，不打断它；预渲染结果就绪前照常活渲，就绪后才改贴预渲染结果。「就绪」按当前播放位置判：从当前位置起 1 秒（不足 1 秒到片段结束）都有预渲染结果覆盖。预渲染集合只增不减，播放中不把卡移出集合。

## 重管线：预渲染

- 每张卡单独保存，只保留实体部分，其余透明。
- 预渲染只在闲时进行，不服务用户的即时交互。打开项目、测量卡片时先给每张重卡产一套稀疏的轨道流；之后要补的只在暂停时产，播放时不产；稀疏版排在满密度版前面。桌面版靠页面在播放中每 2 秒向预渲染进程发一条保活（`PLAYHEAD_KEEPALIVE_MS`；播放头下有缺口时另报）来判断用户还在播放，所以整段播放里预渲染进程一直是「在播」，停了保活 5 秒转回空闲。
- **不同环境的结果不混用**：预渲染结果的键里带着渲染它的**环境指纹**（操作系统、GPU 基础类别、Chrome 主版本）。**一张卡的轨道流只出自一种环境（卡片级指纹锁）**：最先为这张卡产出轨道流的环境锁定它，这张卡剩余的帧只能由指纹相同的节点接着做。
- 拿不到这一帧时照下面的兜底顺序处理，不因为节点还在做而等待。
- 预渲染结果只有一种形态：**轨道流**，播放、暂停、拖动都贴它。每张或每组重卡一条上下拼合 alpha 的 H.264 视频流，裁到实体框，从这条流自己的第一帧起每 15 帧一个分段；单卡流的第一帧就是片段的第一帧，组流、依赖下层的流的第一帧是这条流盖住的那一段的第一帧。清单记着这条流的第一帧，分段号按「这一帧减去第一帧」算；最后一个分段到这条流自己的最后一帧为止，可以不满 15 帧。不为任何卡存每帧的 HTML 快照。
- 每条流有两版，用同一个键：**稀疏版**每个分段只截一张（分段的第一帧），其余帧重复它；**满密度版**每帧都截。清单里每个分段记着自己是哪一版；满密度的分段产出来以后在分段边界换上。
- 怎么产，按卡分：remotion 式的卡不从挂载帧回放；画面全在画布里的卡（画布卡）产流一律直接从画布取像素送进编码器；独立卡单独产流；依赖下层的卡连同下层一起渲染来产流，流只含目标卡改动的那一块区域，这段时间里下层任一控件变了就作废重产。转场和套在视频上的素材效果卡（源依赖卡），连同它用到的视频一起渲，各产一条单卡流。
- **任务切分长度**（2026-10-14 用户定）：`motion` 式的卡产流任务拆分至少管 30 秒（30fps 下 900 帧，不足 30 秒整张卡一口气做完）；`remotion` 式卡保持 8 个分段（4 秒 / 120 帧）一个任务。
- 占位符的位置取流清单里的位置矩形：产稀疏版时每个分段量一个收紧的框。这张卡的流还没有产出来时，占位符照现在的办法定位。
- 预渲染结果的复用：依赖卡的预渲染结果以依赖对象的身份为键，依赖没变就一直复用。
- **推帧补画**：服务端逐帧渲染（`server/bakery/bake.mjs`）里，推过去、不取图的帧，画面有变化的也要真的画一拍：推完补一拍带截图的 `beginFrame`、图丢掉；画面静止的帧不补，并行导出的分片不补，每帧都取图的路一拍不多走。

### 兜底顺序

- 某一层这一拍拿不到精确画面时，按以下顺序取第一个可用且装得下预算的：1. 这一帧的满帧率轨道流；2. 稀疏轨道流（打开项目时先铺满全段的版本，每 15 帧一张；取不晚于这一帧的最近一张，只往回找）；3. 占位符。
- 轻卡在第 1 步之前还有活渲；降级的卡在就绪前照常活渲。
- 预算：轨道流占硬件解码器预算（同时活跃的解码器、解码帧字节）。超出解码器预算的层显示占位符。
- 满帧流这一拍画不出来（解码器不够、清单或分段未到、解码跟不上）时，这一层留着它上一张画面，最多留一个分段的时长（按真实时间算：15 帧除以帧率）；到时还没有新画面就落到占位符。起播和跳转后的第一拍，流的第一帧画出来之前不藏这张卡原来的画面，最多等 500 毫秒，到时还没有就照常藏起来、这一层落到占位符；暂停着的时候把播放头下重卡的这一帧先解好；暂停着的时候更好的结果原地换上（向左对齐，只取不晚于当前帧的画面，属于兜底规则，不影响「停下就精确」；2026-10-14 用户定）。暂停和拖动时也贴流（不只播放中）：这一帧有流、还没追到精确活渲的重卡，活子树藏着、画面由流给；已经回到精确活渲的重卡，它的流平面藏着，照样把这一帧和后面几帧解好，占解码器预算里的名额。
- 来不及的状态持续满 120 毫秒才显示占位符；更短的空档不显示，避免闪烁。
- **旧输入的层不贴**：层表里每条流带生成它的输入签名。片段在时间轴上的位置仍在流键和输入签名里，挪了以后旧流不贴。卡片源码、字体、环境的变化靠渲染节点换键重写层表。

## 剪辑段（2026-10-20）

规则见 `../product/project-model.md` 的「剪辑」「片段」。

- **画面走嵌套场景**：`flattenOverlay` 把剪辑段交成一张卡（`cardId` 为 `@cut`，注册表里没有它），带上被引用剪辑的子项目。舞台给它一个普通的卡片包裹层：框、不透明度、淡入淡出、层序、强调都和卡片一样，包裹层裁掉框外（`overflow: hidden`）；包裹层里挂一个嵌套的场景（`src/render/CutSegmentScene.tsx`），按「被引用剪辑在 `cutOffset + (t − 段起点)` 时刻」渲它的整帧，先在项目画幅里合成，再整块缩放进段的框。
- **同一份代码出同一帧**：预览的舞台、导出页、预渲染页、Agent 看画面用的都是同一份 `FrameScene` / `Stage`。
- **预卷**：`cutOffset > 0` 时，被引用剪辑里在偏移那一刻已经播了一半、要按历史推进的卡，得从它们自己的起点推过来。
- **推帧口径**：被引用剪辑里全是直接求值的卡（和素材）时，剪辑段按直接求值处理，随机跳转不用推；有任何要按历史推进的卡（或嵌套的这种剪辑段）就按状态推进处理。
- **停下就精确**：跳转、暂停、从段中间开始播放时，此刻挂着的、要按历史推进的剪辑段并进「整场景在后台补跑后互换」那一路。
- **测量与预渲染：拆开逐卡**（2026-10-21 用户定）：计划这一侧看的是 `src/kernel/cutFlatten.mjs` 的 `flatPlanProject`。
- **声音走平移展开**：按时间把被引用剪辑里的片段平移、裁到段的窗口里，拼成一份只给混音用的项目（`src/kernel/cutAudio.mjs` 的 `audioProjectOf`），预览的声音层与导出混音都用它。

## canvas 卡的共享 WebGL 渲染器

- 同一个舞台的所有 canvas 卡共用一个 WebGL 上下文和一个 Worker。每张卡自带着色器、各自编译，素材纹理只上传一次。每拍只传时间和变了的参数；Worker 把所有卡画进一张图集，按卡裁成位图交回各自的画布，画完主线程才推进一拍。图层关系仍由舞台管。
- 两条路线都实现，项目选项可切换：
  - **路线 1**（桌面默认）：每个舞台各一个 Worker 和上下文。
  - **路线 2**：编辑界面只开一个 Worker 和上下文，两个舞台共用。
- 导出页自己开一个。
- 粒子卡不进 Worker，仍在主线程画；长的粒子片段靠轨道流。

## 即时渲染与预渲染进程

- 预渲染进程有三种模式：
  - **Agent 模式**（本机只有 Agent）：不预渲染，只按 Agent 的要求即时渲染精确的某一帧。
  - **User 模式**（本机只有用户在编辑）：只预渲染重卡。
  - **Full 模式**（两者都在本机）：优先 Agent 的即时渲染，其次预渲染。
- 用户机上缺省一个预渲染进程，以 Full 模式起（编辑器进程里总有本机 Agent）；模式在进程启动时定下。
- 即时渲染不进文档服务的任务队列，队列只管预渲染。
- 预渲染进程做 User 模式或 Full 模式的预渲染时，同时是一个渲染节点。
- **Agent 优先只是插队**：Agent 的请求只在一个专用渲染实例里走，不提高进程优先级。专用实例每做完一个任务，先从 Agent 队列里按先后取下一个；Agent 队列空时接普通预渲染任务。它不打断正在跑的任务，Agent 任务永远不排在排队中的预渲染任务后面，也永远不占用别的实例，所以用户总能等到预渲染。
- 专用实例做队列任务时按批（4 帧）推进，批与批之间有 Agent 任务就先做 Agent 任务（正在跑的那一批不打断），连着来的 Agent 任务等 1 秒一起做完再接着做队列任务；让路期间照常续租约。
- 专用实例只在自己的 Chrome 开着时接普通预渲染，每次接一项：普通预渲染队列里的一项，或后台那一趟正在做的那张卡里还没开工的一批（4 帧）；做完一个 Agent 任务后空 1 秒才接，免得同一次工具调用里的下一个 Agent 任务白等。
- AI 栏的操作预览（用户点开看的改动前后动图）在专做队列任务的那个实例上插到所有待办之前，不经专用实例；3D 视图的空闲贴图预取排普通预渲染队尾，用户等着看的那一张同样插队。
- 用户交互需要的查询（如选中卡片的实体框）在用户自己的后台舞台上算，不走预渲染进程。
- **单卡画面（bake_card 与 3D 视图贴图）**（2026-10-14 用户定）：播放时从这张卡的轨道流里取（稀疏版也可，向左对齐；无流时先占位；打开 3D 模式后轻卡也产流，贴图随播放时间动，不再定格在 t）；暂停时当场渲当前帧（和 2D 预览「停下就精确」一致）；导出时每帧高清活渲，不从流里取。单张卡片出图统一称为「PNG 快照」，与整场景的 HTML 快照明确区分。
